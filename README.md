# Multi-Horizon Electricity Load Forecasting with Temporal Fusion Transformer

Probabilistic 24-hour-ahead electricity load forecasting for 314 clients,
comparing a Temporal Fusion Transformer (Lim et al., 2019) against seasonal-naive,
LightGBM, and LSTM baselines.

## Problem

Given up to one week (168 hours) of historical hourly load, forecast the next
24 hours as quantiles (p10 / p50 / p90) rather than a single point estimate --
useful for capacity planning, where knowing the *range* of likely demand
matters as much as the expected value.

## Dataset

[UCI Electricity Load Diagrams 2011-2014](https://archive.ics.uci.edu/dataset/321/electricityloaddiagrams20112014)
-- 370 clients, 15-minute resolution, resampled to hourly kWh. 314 clients
retained after filtering for sufficiently complete history. Download
`LD2011_2014.txt` and place it at `data/raw/LD2011_2014.txt` before running
the pipeline (not committed to the repo -- ~250MB raw).

## Approach

| Model | Purpose |
|---|---|
| Seasonal naive (t - 168h) | robust lower-bound baseline -- exploits this dataset's strong weekly periodicity directly |
| LightGBM, direct multi-horizon, residual-vs-naive target, regularized + early-stopped | strong classical baseline |
| LSTM seq2seq | deep learning baseline without attention |
| **Temporal Fusion Transformer** | main model -- variable selection networks, gated residual networks, interpretable multi-head attention, quantile output |

The central question this project answers: *does the added architectural
complexity of TFT actually outperform a well-tuned LightGBM and LSTM on the
same features, and if so, by how much, on which segments, and does it get
typical-case accuracy without the robustness trade-offs seen in the
classical baseline?*

## Results

### Baselines (test set, 24h horizon)

| Model | MAE | RMSE | SMAPE |
|---|---|---|---|
| Seasonal naive | 247.59 | **1658.38** | 13.74 |
| LightGBM (residual, regularized) | **225.66** | 2475.55 | 14.04 |

**Finding:** seasonal naive is a genuinely strong baseline here due to this
dataset's extreme weekly periodicity -- a naive forecast that simply copies
last week's value at the same hour is hard to beat. A LightGBM model trained
to predict the *residual* against that naive baseline (rather than raw load)
improves typical-case accuracy (better MAE) but is less robust to outlier
events, reflected in a worse RMSE even after regularization and early
stopping to rule out simple overfitting. This points to a real modeling gap
-- most likely missing holiday/anomaly signal and the difficulty of a single
model generalizing across 314 clients with very different consumption
scales -- rather than a tuning artifact. This sets a concrete bar for the
deep learning models below: can LSTM/TFT match LightGBM's typical-case gains
without the robustness trade-off?
