# Multi-Horizon Electricity Load Forecasting with Temporal Fusion Transformer

Probabilistic 24-hour-ahead electricity load forecasting for 370 clients,
comparing a Temporal Fusion Transformer (Lim et al., 2019) against seasonal-naive,
LightGBM, and LSTM baselines.

## Problem

Given up to one week (168 hours) of historical hourly load, forecast the next
24 hours as quantiles (p10 / p50 / p90) rather than a single point estimate --
useful for capacity planning, where knowing the *range* of likely demand
matters as much as the expected value.

## Dataset

[UCI Electricity Load Diagrams 2011-2014](https://archive.ics.uci.edu/dataset/321/electricityloaddiagrams20112014)
-- 370 clients, 15-minute resolution, resampled to hourly kWh. Download
`LD2011_2014.txt` and place it at `data/raw/LD2011_2014.txt` before running
the pipeline (not committed to the repo -- ~250MB raw).

## Approach

| Model | Purpose |
|---|---|
| Seasonal naive (t - 168h) | trivial lower bound |
| LightGBM, direct multi-horizon, lag + calendar features | strong classical baseline |
| LSTM seq2seq | deep learning baseline without attention |
| **Temporal Fusion Transformer** | main model -- variable selection networks, gated residual networks, interpretable multi-head attention, quantile output |

The central question this project answers: *does the added architectural
complexity of TFT actually outperform a well-tuned LightGBM on the same
features, and if so, by how much and on which segments?*

## Repo structure

```
├── data/
│   ├── raw/              # place LD2011_2014.txt here (gitignored)
│   └── processed/        # train/val/test parquet, generated by data_pipeline.py
├── src/
│   ├── data_pipeline.py  # load, resample, split
│   ├── metrics.py        # MAE/RMSE/MAPE, pinball loss, quantile coverage
│   ├── baselines.py      # seasonal naive, LightGBM
│   ├── lstm_baseline.py  # (next) LSTM seq2seq
│   ├── tft_model.py      # (next) TFT training via pytorch-forecasting
│   ├── train.py          # (next) unified training entrypoint
│   └── api.py            # (next) FastAPI serving endpoint
├── notebooks/            # EDA, attention-weight visualization
├── models/                # saved checkpoints (gitignored)
├── reports/figures/       # forecast fan charts, horizon-error plots
├── tests/
├── config.yaml
└── requirements.txt
```

## Setup

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

# after downloading the raw UCI file into data/raw/
python src/data_pipeline.py --raw_path data/raw/LD2011_2014.txt
```
